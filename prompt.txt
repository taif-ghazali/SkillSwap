# SkillSwap Android App: Backend Integration and Functional Completion

You are working on the existing SkillSwap project. Your immediate task is to make the existing MIT App Inventor Android application fully functional by integrating it with the already deployed Google Apps Script backend.

## 1. Project reconnaissance

Before modifying anything:

- Inspect the entire existing project directory.
- Locate the existing website source code.
- Locate the existing Apps Script backend source.
- Locate `SkillSwap_MiniProject_Team_Reviewed.aia`.
- Locate existing Figma exports and design references.
- Read the backend API implementation and existing website API integration.

Do not create a new application from scratch.

Do not overwrite or restructure working website or backend components.

## 2. Non-negotiable architecture

Both the website and Android application MUST use:

- The same existing Google Apps Script deployment.
- The same existing `/exec` API endpoint.
- The same production Google Spreadsheet.
- The same API contract and authentication mechanism.

Absolutely do not create another spreadsheet, Apps Script project, backend deployment, or mock database.

The website is already operational. Treat its existing integration as the reference implementation.

## 3. Configure the MIT App Inventor application

Inspect the existing `.aia` project and its blocks.

Configure:
- `global apiUrl`
- `global apiKey`

Retrieve the correct values from the existing project configuration and backend source. Do not invent credentials.

Implement and verify the existing `callApi` and `handleReply` procedures.

Ensure:
- Correct GET/POST request construction.
- Correct JSON encoding and decoding.
- API key and action parameters are transmitted correctly.
- Loading states and error handling work.
- Responses update the correct application components.
- Navigation and application state remain consistent.

Preserve the existing application design and logic wherever possible.

## 4. Complete the application functionality

Test every existing workflow against the actual live backend:

1. University email login and registration.
2. Profile loading and persistence.
3. Teaching skills and learning interests.
4. Available tutor discovery and skill search.
5. Publishing teaching slots.
6. Booking a session.
7. Cancelling a booking.
8. Session listings and status updates.
9. Tutor and learner confirmations.
10. Credit reservation and transfer.
11. Wallet and transaction history.
12. Ratings and tutor review display.

The website and app must produce consistent results when accessing the same accounts and data.

Do not merely test whether HTTP requests succeed. Verify actual application state and corresponding spreadsheet records.

## 5. Testing and safety

Use clearly labelled disposable QA accounts and slots.

Never delete or modify genuine user records.

Clean up only the QA records created during your testing, without disturbing existing data or legitimate transactions.

Verify that:
- Credits cannot be double-spent.
- Duplicate bookings are prevented.
- Cancellation correctly restores credits where applicable.
- Ratings persist.
- Profiles survive application restarts.
- Existing website functionality remains unaffected.

Do not claim a feature passes unless it has actually been tested.

## 6. Deliverables

At completion, provide:

- Updated MIT App Inventor `.aia` project.
- Android APK if the available build workflow supports it.
- A complete list of implemented functionalities.
- Live integration test results.
- Known limitations or remaining bugs.
- Exact instructions for importing the updated project into MIT App Inventor and installing the APK.

Preserve the original `.aia` as a backup.

## 7. Scope restrictions

This phase is exclusively about making the existing Android application work with the existing backend.

Do not redesign the app using Figma yet. Do not rebuild the website. Do not modify the backend API contract unnecessarily. Do not create another production environment.

**Definition of done:** The existing Android application successfully completes the entire SkillSwap user journey using the same live accounts, database, credits, bookings and ratings as the website.
