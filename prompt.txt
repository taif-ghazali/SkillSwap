# PART 1: REPOSITORY AUDIT AND PRESERVATION

Before making changes:

1. Inspect the complete repository and its folder structure.
2. Identify the current frontend architecture, routes, components, state management and local persistence.
3. Identify existing business logic and implemented features.
4. Identify incomplete functionality, duplicated logic and defects.
5. Run the existing application, tests and production build.
6. Establish a Git checkpoint if Git is initialized. Do not overwrite existing work without preserving it.

Do not:
- Rebuild the frontend from scratch.
- Replace the existing design system.
- Remove working features.
- Replace real functionality with static mock screens.
- Introduce unnecessary dependencies.
- Claim a feature works without testing it.

The existing SkillSwap website must remain visually recognizable.
